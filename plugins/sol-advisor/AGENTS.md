## Read this before editing anything here

**This directory is inherited.** Everything under `plugins/` and `.agents/` came from the
repository this one was forked from; the Prime Agent package in `skills/` was built on
the standing evidence that installing it changes nothing here. Resolve upstream from the
checkout rather than from a name written in a file that travels between forks:

```sh
git remote get-url upstream 2>/dev/null || echo "no upstream remote configured"
```

Before touching anything here:

```sh
git diff origin/main -- plugins .agents    # expected: empty
sh plugins/sol-advisor/scripts/verify.sh   # expected: exit 0
```

Two consequences that are easy to get wrong:

1. **Never fold a fix for this directory into a feature PR.** If the verifier is red for
   a reason you did not cause, fix it in its own PR. Folding it in destroys the
   byte-identity that the feature PR asserts.
2. **Every file added here is upstream merge-conflict surface.** This doc and its README
   are themselves fork-local additions; weigh anything further against that.

## Scope

A Codex plugin implementing capability-routed delivery. A primary Sol session keeps
architecture, decomposition, verification and acceptance; implementation goes to either
a native Terra custom-agent thread or — only on explicit per-request opt-in — a
user-visible Luna app task.

## Conventions

- POSIX `sh`. Verify with `sh -n`.
- The installer must **refuse** rather than overwrite: a modified, non-regular, or
  symlinked destination stops it, with no partial mutation.
- `inspect-agent-runtime.sh` prints an allowlisted JSON object and never prompts,
  messages, environment variables, tokens, or arbitrary rollout payloads. Keep it that
  way; it exists to be safe to run.
- No silent fallback anywhere: a missing, stale, or unobservable role/model/effort stops
  the lane with an actionable error.

## The other contract in this repo

`skills/sol-orchestration/` is a Prime Agent capability package. It is invisible to
Codex and shares no code with this plugin. A session should load exactly one of the two,
decided by the harness it runs in — say which out loud when it is ambiguous.
